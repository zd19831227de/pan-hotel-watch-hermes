# Pan Hotel Watch 运营人员操作手册

Pan Hotel Watch 是一套生产级监控控制台：读取真实的携程 / 美团 / 飞猪 EBK
后台经营数据与携程公网竞品酒店页面价格，保存可信结果，推送简明的飞书消息，
并为「非直连」EBK 账号提供一条严格受控的飞书调价审批流程。

运营人员可以通过三种方式使用系统：

- **Web 运营控制台**：配置、手动读取、轮询状态、趋势图；
- **定时飞书推送**：EBK 简报、竞品价格卡/表格、评价汇总、BI 日报；
- **飞书 @机器人助手**（默认 Hermes 模式）：自然语言问答、数据卡、趋势图卡、
  按需周报、调价审批指令。

系统**不提供**：前端调价执行按钮、通用 API 执行入口、AI 自动定价、AI 定时
日报、模型自学。竞品变价参考卡在生产环境使用**规则化**生成；Hermes 可以用
自然语言解释查询结果，但价格数字永远来自落库的可信读取。

## 每日检查

1. 打开运营控制台；
2. 确认浏览器账号状态正常；
3. 确认 EBK 监控与竞品监控只在预期的监控组上启用；
4. 需要立即核对数据时使用「手动读取」；
5. 浏览器账号与 webhook 配置完成后再开启定时轮询。

## 浏览器账号

浏览器账号按用途分两类：

- **EBK 账号**：登录携程 / 美团 / 飞猪 EBK 后台，读取经营数据；
- **竞品公网账号**：登录携程公网，读取竞品酒店页面价格。

每个 EBK 账号还需标注连接模式：

- **未确认**（默认）：新建与存量账号的默认值，系统按直连账号对待，不允许
  自动改价；
- **直连账号**：只读数据并生成规则化建议；
- **非直连账号**：唯一可以在飞书卡审批后进入自动改价链路的模式。

Web 控制台没有任何审批、自动改价、保存、提交或 OTA 写入按钮。调价执行只能
从飞书审批卡发起。

一个启用中的竞品监控组必须绑定一个竞品公网账号；不要把同一个浏览器账号
同时绑定到多个启用中的竞品监控组。

浏览器登录态是单实例资源。系统报告登录、验证、短信、扫码或风控状态时，
请在浏览器窗口人工处理登录，然后重试读取。

## 飞书群绑定

用于运营查询或调价卡的每个飞书群，都应在 Web 控制台绑定正确的监控配置：

- 在目标 EBK 浏览器账号上绑定 `feishu_chat_id`，用于手动调价指令（如
  `@机器人 把今天高级大床房调到420`）;
- 在竞品监控组上绑定 `feishu_chat_id`，用于竞品推送与竞品触发的参考卡；
- 在竞品监控组上选择「调价 EBK 账号」，用于竞品触发的调价参考卡。

一个正常的运营群管理一家门店的上下文：EBK 数据、竞品价格、日历价状态、
调价写入策略。「调价 EBK 账号」只控制可写价的调价链路；它未设置、为直连
或未确认时，EBK、竞品、日历价的只读查询照常可用，写价始终被禁止。

一个飞书群覆盖多家门店时，助手会先追问店名（例如「静里」或「澜江路泉吉」）
再查询数据，不会把不同门店的数据混在同一个回答里。

默认飞书入口模式是 `hermes`：Hermes 网关接管 @机器人 自然语言会话，后端
只处理卡片动作与结构化调价指令。**不要**同时运行旧版 `feishu-listener`
worker 或其他机器人监听同一个飞书应用。

## 飞书 @机器人 问答（Hermes 模式）

群里常用的运营问法：

```text
@机器人 今天出租率多少？
@机器人 昨天好评几条？
@机器人 竞品最新价
@机器人 最近三天竞品趋势
@机器人 竞品有没有明显变化？
@机器人 上周简报
@机器人 今天三端简报
@机器人 三 OTA 今日经营
@机器人 本店今天房型价格
@机器人 本群盯着哪家店？
@机器人 盯盘服务正常吗？
```

典型行为约定：

- 「今天三端简报」「三 OTA 今日经营」走三平台联合 EBK 简报；单指标（出租率、
  ADR、RevPAR、销售额等）走对应 EBK 读取工具。回答形式取决于工具返回，普通
  提问不保证每次都发起浏览器现读；
- 「本店今天房型价格」指已落库的本店/竞品价格上下文，不是未来日历价矩阵；
  只有明确问到未来日历价才使用日历价工具；
- 好评/差评条数来自最近一次落库的 EBK 快照，字段口径是**昨日**评价数，不是
  今日实时增量；
- 竞品最新价、趋势、变化分析使用对应的可信落库数据与独立工具；只有用户
  明确要求刷新或立即读取时才触发浏览器现读，普通提问不会静默刷新；
- 竞品历史与趋势问题返回**趋势卡**：图表 PNG 生成成功时带折线图，否则回退
  分组文字趋势块；
- 周报**仅在要求时生成**，系统不自动推送 AI 日报；
- `@机器人 调价建议` / `@机器人 调价` 只解释变价提醒由竞品轮询自动触发，
  不会按需评测。

当前网关路由是「模型调用前的确定性上下文注入 + MCP 执行前的硬门禁」。
与酒店无关的问题（例如天气、翻译）留在 Hermes 通用能力内，不会调用
Pan Hotel MCP；有歧义的酒店问题会追问澄清而不是猜测。

## EBK 数据监控

EBK 监控支持：

- 可编辑推送标题；
- 可编辑飞书 webhook；
- 手动读取；
- 定时轮询；
- 飞书卡内附带最近一次运行状态与读取时间。

EBK 监控是纯只读操作：不报名促销、不取消活动、不改促销设置、不改价、
不写任何 OTA 页面。

## 竞品价格监控

竞品监控支持：

- 可编辑监控组标题；
- 可编辑移动卡 webhook 与桌面表格 webhook；
- 可编辑本店与竞品酒店配置；
- 手动读取并推送；
- 定时轮询；
- 最新可信价；
- 可信价趋势图。

可信价只来自可见 DOM 房价（来源 `room_rate_dom_display_price`）。纯文本或
不确定的价格会保存待复核，但不参与趋势与运营结论。

携程在同一房价行显示优惠金额（如 `优惠32`）时，竞品监控会随房价一并保存并
在飞书推送中展示：

```text
无早 ¥416（优惠32） | 含早 ¥481（优惠36）
```

飞书卡/表格里价格与优惠数字都会加粗强调。查不到可见优惠时留空，不会用旧
数据编造或回填。

## 价格变化提醒

控制台可以检测竞品价格是否变化到需要运营关注。系统只比较最新一轮可信
竞品读取与上一轮读取，且只用可信 DOM 房价：

```text
is_trusted=true
source=room_rate_dom_display_price
```

超过配置阈值时，控制台展示：

- 本店当前价；
- 竞品上次价；
- 竞品本次价；
- 变化金额与百分比；
- 建议调整幅度；
- 建议调整后价格；
- 触发原因；
- 是否建议人工关注；
- 绑定账号类型与写入策略。

建议与调价参考摘要是**规则化**生成的：默认部署下，后端不为变价提醒调用
AI 模型。

- 竞品**涨价**：仅提醒。展示竞品变化与幅度，不建议本店跟涨，也不产生任何
  可执行的审批路径。
- 竞品**降价**：可推送调价参考卡，卡片只有「**自定义调价**」和「**暂不
  处理**」两个选项；运营必须输入或确认目标价之后，才会出现任何执行确认。

手动检测默认静默，除非后端请求显式设置 `push_to_feishu=true` 才推送飞书。

## 飞书调价审批

支持的群指令：

```text
@机器人 调价建议
@机器人 调价
@机器人 把今天高级大床房调到420
```

价格变化提醒和调价参考卡由竞品价格轮询自动触发。轮询成功入库后，系统比较
当前 run 与上一 run，超过阈值时自动发送价格变化提醒和调价参考卡。

`调价建议` / `调价` 不会临时检测价格变化，也不会临时生成审批卡，只说明
自动触发机制。`把今天高级大床房调到420` 会为该房型、日期和目标价创建手动
审批卡，并可绑定当前飞书群用于后续参考卡投递。

- 未确认或直连账号：卡片只展示建议与人工处理指引，不出现「通过」；
- 非直连账号：竞品触发的参考卡只有「自定义调价」和「暂不处理」，没有
  一键「通过」；
- 「自定义调价」打开价格输入表单；运营提交目标价后，系统先重跑安全检查，
  再展示任何执行确认。

运营确认目标价后，后端依次执行：

```text
预览 -> 飞书审批 -> 执行预检 -> 页面空跑 -> 写价 -> 飞书结果通知
```

过程中遇到登录、扫码、短信、验证码或风控验证，链路停止并发送「需要人工
处理」结果；EBK 价格页结构不明确时以「需要复核」停止。

## 趋势图

### Web 控制台

竞品趋势图只显示近期的可信 DOM 价格，并拆分为四个视图：

- 今日无早；
- 今日含早；
- 明日无早；
- 明日含早。

每个监控组有自己的酒店配置与趋势区间；切换监控组会刷新该组的最新价与
图表。

### 飞书趋势卡

在飞书里问竞品历史、近期趋势或要图时，助手发送由同一批可信 DOM 价格构建
的趋势卡：优先 PNG 折线图（今日/明日 × 无早/含早分面板）；运行环境不支持
图表生成时回退分组文字趋势块，查询本身不会失败。

## 日历价问答

运营可以在飞书里问：

```text
@机器人 未来15天日历价怎么样
@机器人 查一下日历价
@机器人 日历价是不是设置了自动轮询间隔？
@机器人 查一下澜江路泉吉日历价状态和上次读取时间
@机器人 现在刷新一次未来15天日历价
```

默认行为：

- `get_calendar_price_watch_status` 读取日历价状态/配置：
  `auto_poll_enabled`、`schedule_interval_minutes`、`future_days`、调度器
  状态与最近读取时间；
- `get_calendar_price_latest` 读取最近落库的日历价矩阵；
- `run_calendar_price_watch_once` 只在运营明确要求最新、刷新、立即读取或
  跑一次时使用；
- 会话内刷新默认 `push_to_feishu=false`，回复以运营卡形式发回当前群；
- 日历价回答是只读的，不会产生调价审批、空跑、执行或本店涨价建议；
  日历价状态不要求调价 EBK 账号可写。

## 周报

运营可以在飞书里问：

```text
@机器人 上周简报
@机器人 经营分析
@机器人 周报
```

系统基于落库的 EBK 运行、竞品轮询记录与变价提醒，为绑定门店生成**上一个
自然周**的简报。它是按需查询，不是定时自动推送。某个模块当周没有可信运行
时，简报会写「暂无数据」，不会编造数字。

## 刻意不做的事

当前 V1 范围刻意排除：

- 没有运营输入目标价的 AI 自动定价或执行；
- 自动报名/取消促销活动、改促销价格或设置；
- AI 定时酒店日报；
- 基于聊天历史的模型自学定价决策；
- 「立即调价」「写入携程」之类的前端按钮；
- 面向普通调用方的通用空跑/执行 API 入口。

完整调价安全规则：
[AGENTS.md — 调价安全契约](../AGENTS.md#调价安全契约pricing-safety-contract--authoritative)。

## 安全排障

在 Windows 主机上使用：

```bat
scripts\status.bat --nopause
scripts\show-logs.bat --nopause
scripts\stop-all.bat --nopause
scripts\start-all.bat --nopause
```

密钥只放在 `.env`。不要提交 webhook 地址、Cookie、浏览器 profile、验证码
或截图。
