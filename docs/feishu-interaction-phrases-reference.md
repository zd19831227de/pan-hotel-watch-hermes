## 二、分模块触发词详解

### 3.1 调度状态（get_watch_scheduler_status）

- **精确匹配**（整句等于）：`盯盘状态`、`监控状态`、`轮询状态`
- ❌「调度状态」「系统在跑吗」→ general，不触发任何工具
- ❌「盯盘的状态」→ 多一个"的"就不精确匹配，落入其他分支

### 3.2 今日简报（get_operator_hotel_overview）

- 精确：`今日简报`、`当日简报`
- 子串：`经营简报`（单独说即可命中）
- ❌「今天酒店整体情况」「今日概览」「今天概览」→ 不触发（概览类词只是 EBK 分支
  内部的子词，单独说判 general/ambiguous）；改说「今日简报」「经营简报」

### 3.3 本群绑定（resolve_feishu_chat_context）

- 词表：`本群绑定 / 这个群绑定 / 绑定了哪家 / 绑定哪家 / 群绑定 / 本群绑 / 绑了哪家 / 绑哪家`
- ❌「这个群管哪家店」→ general；改说「本群绑了哪家」

### 3.4 今日预定与退单（默认现抓、自动拉起浏览器）

**退单词表**（get_refund_status）：`退单 / 退了几单 / 取消几 / 取消多少 / 退单量 / 退款单`

**预定词表**（get_today_reservations）：`今日预订 / 今日预定 / 今天订了 / 今天预定 / 今天预订 / 今日订了 / 订了几单 / 预订单 / 新订几单 / 今天订多少 / 今日订多少`

规则：

- 两种工具**默认每次先现抓再读**（单平台抓该平台；不点名平台=并发抓携程+美团+飞猪，
  按群绑定店铺账号**自动拉起浏览器**，浏览器未开会自动打开）。
- 同一句同时含"退单词 + 预定词"（如「今天预定和退单情况」）→ 两个工具都放行，一起作答。
- 时段问法（「凌晨退单多吗」「上午6到12点退了几单」「退单集中在几点」）→ 按快照
  `by_hour` 桶回答。
- ❌「取消了几单」→ "了"字隔断「取消几」→ general；改说「今天取消几单」或「今天退单多少」
- 带历史日期范围（昨天/上周等）→ 走已落库历史，**不再现抓**。

### 3.5 携程 EBK 指标现读（read_ebk_datasets，读已落库数据，不开浏览器）

先要命中 **EBK 词表**之一：`ebk / 携程后台 / 美团后台 / 飞猪后台 / 经营简报 / 经营报告 / 出租率 / 入住率 / 收益概览 / 销售数据 / 销售排名 / 竞争圈 / 榜单 / 排名 / 促销 / 活动 / 神券 / 金字塔 / 广告投放 / adr / 平均房价`

✅ 例：`今天出租率多少`、`竞争圈排名`、`竞争圈榜单`、`金字塔今天投放情况`、`参加了哪些促销`、`携程促销`

注意「竞争圈排名」口径模糊时机器人会先追问是哪类榜（销售排名榜/经营对比/流量排名），选中即可。

### 3.6 EBK 全量刷新（run_ebk_watch_once，开浏览器、可能数分钟）

**EBK 词表**（同上）再命中刷新词：`刷新 / 跑一次 / 完整刷新 / 更新全部`

✅ 例：`刷新EBK`、`跑一次EBK`、`刷新一下EBK数据`、`完整刷新EBK`、`更新全部EBK数据`、`携程后台数据刷新一下`

刷新成功后**本轮锁死 ebk_refresh**：紧接着要读单模块明细（如竞争圈榜单）必须**新发一条**
消息（如「竞争圈榜单」）让路由重新分类。

### 3.7 三端 / 单平台（get_ebk_joint_analysis_context）

- 三端触发：`三端 / 三平台 / 三个平台 / 各平台 / 多平台`，或一句话里出现 **≥2 个平台名**
- 单点名美团/飞猪：**EBK 词表词 + 美团/飞猪**，如 `美团经营简报`、`美团有什么活动`、`飞猪促销`、`美团神券`
- ❌「美团经营数据」「刷新美团」「美团今天怎样」→ ambiguous（"美团"单独不成意图）；改说「美团经营简报」
- ✅「刷新三端 / 刷新三平台」→ 联合分析（模型可带现读参数刷新后再分析）
- **禁止**用 read_ebk_datasets 答美团/飞猪——那是携程监控组数据集。

### 3.8 周/月/昨日历史（get_ebk_period_read，只读落库快照，不开浏览器）

**周期词 + 数据词双命中**才触发：

- 周期词：`昨天 / 昨日 / 前天 / 前一日 / 本周 / 这周 / 上周 / 近7天 / 近一周 / 最近一周 / 过去一周 / 本月 / 这个月 / 上月 / 上个月 / 近30天 / 近一月 / 最近一个月 / 过去一个月 / 按周 / 按月 / 周度 / 月度 / 周报 / 月报`
- 数据词：`经营 / 排名 / 榜单 / 生意 / 销售 / 间夜 / 出租率 / 入住率 / 收益 / 销售额 / 预定量 / 预订 / 客单 / 转化率 / 流量 / adr / 平均房价`

✅ 例：`本周经营数据`、`上周排名`、`昨天经营怎么样`、`近7天出租率`、`本月转化率`、`上周流量`、`近7天预订量`、`最近一周销售`

- ❌「本周订单趋势」→ "订单"不在数据词表 → ambiguous；改说「本周销售 / 近7天预订量」
- ❌「9月1日到9月7日经营」→ 自由日期段没有周期词 → ambiguous（当前路由不支持，
  见第六节已知边界）；改说「近7天经营」「本周经营」
- 昨日经营/排名由每天 09:30 日终轮次落库；查不到时机器人会用 period=day 现读页面"昨日数据"块。

### 3.9 竞品价格（get_competitor_latest_prices / analyze_competitor_price_change / get_competitor_price_trend）

先命中竞品词：`竞对 / 竞品 / 竞争酒店 / 竞店`（或「本店」+价格词）

| 子意图 | 触发词 | 工具 |
|---|---|---|
| 现价（读已保存价格，快） | 无特殊词，默认 | get_competitor_latest_prices |
| 相邻轮询变化 | `变化 / 变了 / 提醒 / 预警 / 要不要关注` | analyze_competitor_price_change |
| 趋势/历史序列 | `趋势 / 涨幅 / 跌幅 / 波动 / 曲线 / 最近三天 / 历史价格` | get_competitor_price_trend |
| 现爬（开浏览器，慢） | `刷新 / 现爬 / 现在读 / 跑一次 / 更新` | run_competitor_watch_once |

✅ 现价：`竞品价格`、`现在竞品多少钱`、`本店房型价格`
✅ 变化：`竞品最近变化`、`竞品变化情况`
✅ 趋势：`竞品价格趋势`、`竞品最近三天价格趋势`
✅ 现爬：`刷新竞品`、`现爬一下竞品`、`现在刷新竞品价格`、`更新一下竞品价格`、`竞品跑一次`、`现在读一遍竞品`、`刷新一下竞品价格`

- ⚠️ **不触发现爬的近似说法**（只读旧快照）：`重新抓竞品`、`立即读竞品`、`抓取最新竞品价格`
  （路由刷新词表里没有"重新抓/立即读/抓取"）——想真刷新请用上面 ✅ 现爬句式
- ❌「竞品有没有变」「竞品涨了吗」→ 落入"现价"而非"变化"；改说「竞品最近变化」
- ❌「我们今天多少钱」→ general；改说「本店房型价格」
- 「本店/今天房型价」**禁止**用日历价工具回答（门禁硬拦截）。

### 3.10 日历价（未来15天矩阵，只读）

触发词：`日历价 / 未来15天 / 未来十五天 / 未来房价`

- 加 `状态 / 轮询 / 间隔 / 配置 / 上次` → 查轮询状态（get_calendar_price_watch_status）
- 加 `刷新 / 立即读 / 现读 / 跑一次 / 更新` → 刷新（run_calendar_price_watch_once，开浏览器，
  Hermes 强制不推 webhook）

✅ 例：`日历价`、`未来15天价格`、`日历价监控状态`、`刷新日历价`、`现读日历价`

### 3.11 评价

| 想问 | 话术 | 工具 | 规则 |
|---|---|---|---|
| 待回复评价数 | `携程待回复评价`、`美团未回复评价多少`、`飞猪评价` | pending_review_count | **评价词（评价/点评…）+ 平台名（携程/美团/飞猪）双命中** |
| EBK 好评/差评条数（昨日口径） | `EBK好评差评` | get_ebk_latest_result | 须命中 EBK 词表 + 好评/差评/点评/评论 |

- ❌「今天好评几个」→ ambiguous（"好评"不在任何触发词表）；改说「EBK好评差评」
- ⚠️「携程点评怎么样」判为**待回复数**（评价管理口径），不是好评差评条数
- 平台名必填，只说「待回复评价」不点名平台不会命中。

### 3.12 经营原因分析（get_operator_analysis_context）

命中条件：酒店数据词 + `为什么 / 原因 / 怎么回事 / 分析` + `订单 / 经营 / 收益 / 销售 / 出租率 / 入住率`，且未点名多平台

✅ 例：`为什么订单弱`、`订单为什么这么少`
❌「要不要跟价」→ general；改说「为什么订单弱」（分析）或「竞品价格」（先看价）

### 3.13 知识库（rag_search）

触发词（窄词表）：`退款 / 退订 / 退房 / 取消订单 / 取消预订 / 改签 / 入住流程 / 退房流程 / 入住时间 / 退房时间 / 几点入住 / 几点退房 / 最早入住 / 最晚退房 / sop / faq / 常见问答 / 常见问题 / 政策 / 规定 / 制度 / 审批流程 / 客诉 / 投诉 / 积分 / 会员等级 / 会员体系 / 知识库`

✅ 例：`退政策是怎样的`、`入住流程几点退房`、`取消订单怎么算`

注意「退款/取消订单」走知识库，**不要**用它问当日退单数（当日退单用 3.4 的退单话术）。

自学习（投喂）：

- 发链接/文本 + 「学习/提炼/蒸馏这个」→ 一次性入库
- 「每 X 小时学一次 <链接>」→ 定时学习源（最小间隔 30 分钟）
- 「学过什么/有哪些学习源」→ 清单

### 3.14 手动调价审批卡（create_manual_pricing_approval / dispatch_watch_feishu_event）

**调价词（调到 / 目标价 / 改价）+ 对象词（房型 / 房间 / 元 / 块）双命中**

✅ 例：`把今天大床房调到420元`、`把今天高级大床房型调到420`、`大床房今晚调到420块`

- ❌「把今天大床房调到420」（不带"元/块/房型"）→ general，不建卡
- ❌「今天大床房改价420」「目标价420 大床房」→ 不命中；务必带"元"或"块"
- 「调价」「调价建议」→ ambiguous（**设计如此**：参考卡由竞品轮询自动触发，不按需评估）
- 改价意图信息不全时机器人会转发后端澄清，不会猜字段建卡。

### 3.15 周报（get_weekly_operator_briefing）

✅ `EBK周报`（EBK 词 + `上周 / 周报`）
- ❌「周报」单独 → general
- ⚠️「上周经营简报」会被周/月历史分支抢先（上周+经营）→ 查的是历史范围而非周报

### 3.16 金字塔出价与调价（网关直发后端指令，不走 LLM 路由）

这类指令在飞书网关层就被转发给后端指令处理器（hermes `router/manual_price_routing.py`
↔ 后端 `pyramid_bidding/commands.py` 同口径窄闸门），**不进 Hermes LLM、不受上面
EBK 词表约束**；话术已跑真实分类器验证（2026-09-08）：

- 查询出价列表：`金字塔出价`、`金字塔推广列表`、`查金字塔出价`、`看一下金字塔推广计划`
  → 回出价列表卡（浏览器只读列表页）
- 调价（名称+价格齐全）：`金字塔调价 14--16 出价调到6`、`把金字塔14--16的出价调到6元`、
  `金字塔 20--22 调到4.2`（可省「出价」二字，结尾带不带「元/块」都行）→ 审批卡
  （仅 non_direct 账号出现执行按钮），确认后走 preflight → dry-run → 执行 → 回读校验
- 字段不全（`金字塔调价`、`金字塔出价调到6`）→ 回「信息不完整」补全卡（含示例）
- 出价超出 0.1~99 元（`金字塔出价调到100`）→ 文字提示重发
- `金字塔今天投放情况怎么样` 等数据问答**不转发**，留给 Hermes 读 `ad_pyramid`
  数据集（见 3.5）

### 3.17 活动促销（携程 EBK 促销中心）查询与立减调整（网关直发，不走 LLM 路由）

同金字塔口径：飞书网关窄闸门（`manual_price_routing._is_promotion_adjust_related`
↔ 后端 `promotion_adjust/commands.py` 同口径）直转发后端指令处理器；话术已跑
真实分类器验证（2026-09-09）：

- 查询已参加促销：`促销列表`、`活动促销列表`、`查询促销列表`、`看看促销列表`
  → 回已参加促销列表卡（浏览器只读促销中心）
- 调整立减（名称+百分比齐全）：`促销调整 天天特价 立减调到5`、
  `把促销门店新客立减的立减调到35%`（可省「促销调整」前缀）、`促销天天特价调到5`
  → 审批卡（按钮「确认调整促销 / 暂不调整」），确认后走 preflight → 页面核验
  dry-run → 填立减保存 → 回读校验
- 仅支持单条「立减 X%」规则的促销；多条规则/红包折扣类提示转人工（EBK 促销中心处理）
- 立减百分比限 1~95（`促销调整 天天特价 立减调到0.5` → 文字提示重发）
- 字段不全（`促销调整` 四个字）→ 回「信息不完整」补全卡（含示例）
- `促销效果` / `促销报名` / `已参加促销` / `参加了哪些促销` 等数据问答**不转发**，
  留给 Hermes 读链路（见 3.5）

## 四、会真正使用浏览器的话术清单

| 动作 | 话术 | 耗时/行为 |
|---|---|---|
| EBK 全量刷新（10 模块） | 刷新EBK / 跑一次EBK / 完整刷新EBK / 更新全部EBK数据 | 数分钟；期间不要重复发；完成后只回一句确认+数据时间 |

## 六、已知边界（写文档时核实，供后续修复参考）

1. **自由日期段不支持**：「9月1日到9月7日经营」无周期词 → ambiguous。SKILL 里写了
   date_from/date_to 传参规则，但路由层不放行，需先澄清。可考虑把日期正则加入周期词。
2. **暂停/恢复监控、全局配置、最近活动不可路由**：`pause_watch / resume_watch /
   get_operator_watch_configuration / get_operator_recent_activity` 在
   `PAN_HOTEL_TOOLS` 白名单里，但 `route_domain_intent` 没有任何分支放行它们——
   飞书里说「暂停竞品监控」「所有监控组」会被门禁拦截。这些操作目前只能去 WebUI。
   （业务指南 §八 的对应行实际走不通。）
3. **插件旧竞品刷新词表是死代码**：`_COMPETITOR_REFRESH_TOKENS`（含"重新抓竞品"等）
   已无调用方，现权威判定在 domain router；「重新抓竞品」因此不触发现爬。
4. **今日指标词覆盖有限**：「流量/订单/收益/销售额/转化率/间夜」等词单独（不带周期词
   或 EBK 词表词）今天问不出数——要么补进 EBK 词表，要么话术带上已支持词。
