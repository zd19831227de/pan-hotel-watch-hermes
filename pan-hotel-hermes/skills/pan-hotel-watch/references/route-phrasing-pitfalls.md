# 价格类问法的路由坑位与现行口径

## 背景（2026-09-14 收口前）

店长问「携程豪华套房今日房价」被判 `ambiguous`（reason=`hotel_data_needs_clarification`），
所有 pan-hotel MCP 被门禁拒绝，机器人回「不知道」；问「携程本店今日房价」又落到
`competitor_latest`，答成竞品数据。根因：`_PRICING_QUERY_RE` 是 fullmatch，
形态仅限 `[携程|美团|飞猪]的?[今天|今日|明天|明日]?房价(查询|情况|列表|名单|信息)?`，
句中夹房型名/「本店」即失配。

另一个实测事故：问「携程本店今日房价」拿到「2026-09-14 17:04（北京时间）」。
根因是**双重时区转换**——后端落库 `captured_at` 是北京墙上时间（无时区后缀，如
09:04），SOUL 却指示「MCP 返回的 UTC 时间需 +8」，模型照做把 09:04 显示成
17:04。修复：MCP 返回的不带后缀时间即北京时间，直接使用；仅 `Z`/`+00:00`
后缀才 +8（SOUL 与 `watch_api` 已同步收口）。

## 中期形态（2026-09-14 ~ 2026-10-13，已退役）

查价曾改为「确定性指令、不经过 LLM 判断」（网关词表直转后端）。但词表
子串匹配先后劫持图表追问（2026-10-08，`图上需要加上本店…房价个位数`）与
测算问法（2026-10-14，`房型价格提高20元的进单测算` 被答成房价查询——
「测算」不在排除表、「提高」不在调价动词表），排除词永远补不完同义词。
`router/pricing_query_routing.py` / `router/manual_price_routing.py`
两份网关词表已随 2026-10-14 全量 LLM 先行退役删除。

## 现行口径（2026-10-14 全量 LLM 先行）

一切文本消息先进 Hermes LLM（generic_agent）判断，不再有任何词表硬路由；
仅 url_verification 与卡片回调（审批按钮）仍由网关直转后端。LLM 认定是
问价目表现状或固定格式指令时，调 `dispatch_watch_feishu_event` 转发
**运营原话**（payload：`header.event_type=im.message.receive_v1` +
`event.message` 的 message_id/chat_id/content.text，原话一字不改），
后端 `pricing_query_command.py` / `manual_price_command.py` 等词表做
终审识别并出权威卡/人工审批卡。

- 后端终审命中（查价）：句中含「房价/房型价格/房型价/卖价/售价/房态/
  还有房(吗)/房型+多少钱」，平台词、日期词、「本店」、房型名任意语序。
- 平台：恰一个平台词 → 只读该平台；未点名/多平台并列 → 全部已绑定平台。
- 日期：明天/明日/明晚 → tomorrow；今天/今日/今晚/现在/当前/目前 → today；
  默认 today。「查现在」=「查今天」（都是现读今天价目表，卡上标注读取时间）。
  明天口径目前只有携程读的是明天日历页；美团/飞猪产品树无日期切换，仍是当前价。
- 群聊需 @机器人才进 LLM（hermes core require_mention，防闲聊刷屏）。
- `create_manual_pricing_approval` 已列入通用模式禁区：目标价等审批字段
  只能由后端解析运营原话生成，不经 LLM 手拼。

## 问法去向（现行链路下的判断要点）

| 问法 | 去向 |
|------|------|
| `查房价` / `携程本店今日房价` / `看下房态` | LLM 判断问价 → dispatch 原话 → 房价查询卡 |
| `你给我做个测算…房型价格提高20元进单影响`（2026-10-14 生产原句） | LLM 直接用数据工具做测算分析，**不**触发房价查询 |
| `把今天大床房调到420` / `促销调整 X 立减调到5` / `金字塔出价调到6` | LLM 判断固定格式指令 → dispatch 原话 → 后端审批卡 |
| `本店房型现价` / `你读取上一轮的数据` | `get_competitor_latest_prices`（持久化现价/上轮快照） |
| `未来房价` / `携程日历价` | 日历矩阵 |
| `今日平均房价` | EBK ADR 指标（`read_ebk_datasets`） |
| `房价是什么意思` / `房价预测分析报告` | 非数据查询，LLM 直接回答 |

## 处理口径（写给未来的自己）

1. dispatch 转发被后端拒绝（「不是价格命令」）时：停止连打工具，用一句话
   给店长可照抄的规范问法（如「携程本店今日房价」）。
2. 回复读数时间直接用返回值；它已是北京时间。只有带 `Z`/`+00:00` 的才 +8，
   禁止给北京时间再加 8 小时。
3. 读价与改价分两段：查价与固定格式调价指令都走 dispatch 转发原话；
   审批卡由后端解析生成，信息不全的改价意图也走 dispatch 让后端追问。
4. 读价与改价都要按当前账号 `connection_mode` 判断能否自动执行；直连或未确认只能给人工操作建议。
5. 后端 `pricing_query_command.py` 词表仍是 dispatch 终审闸：调整查价口径
   只改后端这一处（网关词表已删除），配套 `backend/tests/domain/
   test_pricing_query_command.py` 同步更新。

## chat_id 获取

MCP 工具要求透传 chat_id。会话上下文没显式给出时，从环境变量 `HERMES_SESSION_CHAT_ID` 读取
当前群标识（同轮 `HERMES_SESSION_CHAT_NAME` 是群名）。该值仅当轮透传给 MCP 工具，
禁止写入记忆、技能正文或任何回复内容。
