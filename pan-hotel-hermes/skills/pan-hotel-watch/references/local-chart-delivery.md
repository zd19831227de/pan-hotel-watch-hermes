# 本地出图 + MEDIA 交付（无图卡通道的模块）

2026-10-13 实测。适用场景：店长要图，但该模块**没有**图卡通道——金字塔投放、BI 未来在手/竞争圈胜负、去年同期按星期对比、竞争圈名次、促销对比等。
价格趋势/涨跌仍必须走 `get_competitor_price_trend(with_chart=true)`（系统渲染的真图卡），不要用本地脚本重绘价格趋势。

## 1. 为什么本地出图是允许的（链路已确认，不是绕过能力）

- 竞品价格趋势的图卡是**唯一**由系统渲染的图卡能力；其他模块后端没有出图入口。
- 本地出图 → 回复正文里带 `MEDIA:<绝对路径>`。插件 `pan-hotel-feishu-session` 的 `transform_llm_output` 钩子对「含真实附件 MEDIA 标签」的回复**不发运营助手卡、放行给网关原生管线**：网关剥掉 MEDIA 行、上传图片、再发清洗后的正文（源码注释里写明 2026-10-09 静里排名图生产实证）。
- 结论：带图的回复天然走原生投递，不要指望它同时被包成卡片；正文仍按短文字规范写（图会随文字一起到群里）。

## 2. 出图配方（本 profile 已有先例，照抄即可）

- 脚本落 `<profile>/scripts/plot_*.py`，图片落 `<profile>/charts/<store>_<topic>_<yyyymmdd>.png`。已有先例：`plot_ctrip_ranking_bars.py`、`plot_own_vs_shuiyunlan.py`、`plot_own_vs_comp_hourly.py`。
- 中文字体（不设就是方块）：`matplotlib.use("Agg")`；`plt.rcParams["font.sans-serif"]=["Microsoft YaHei","SimHei","SimSun"]`；`plt.rcParams["axes.unicode_minus"]=False`。写脚本前先探一次本机可用中文字体，别猜字体名：`python -c "from matplotlib import font_manager as fm; print(sorted({f.name for f in fm.fontManager.ttflist if any(k in f.name for k in ('SimHei','YaHei','SimSun','Noto','Source Han','KaiTi','FangSong'))}))"`（本机实测有 Microsoft YaHei / SimHei / NSimSun / Noto Sans SC）。
- 存图必须 `fig.savefig(out, facecolor="white", bbox_inches="tight", pad_inches=0.35)`——否则用 `fig.text` 写在图下方的结论/脚注会被画布下边缘裁掉（实测被切掉一行）。
- 图例别放左上/右上：顶部有「领先/持平/输」这类状态标签行时必与图例打架（实测重叠）。把图例移到轴下方：`ax.legend(h+l, l+l, loc="upper center", bbox_to_anchor=(0.5,-0.30), ncol=3, frameon=False)`，并把 `fig.subplots_adjust(bottom=0.40~0.42)` 留够空间。
- 缺失数据不要画成 0：柱高给 0、并在该位置竖排标注「无基线 / 未读到」，否则读者会把缺失当成「真的是 0」。去年基线为 0 或 null 一律按缺失处理。
- 图内要素：主标题（店名+主题）、副标题（口径 + 读取/数据时间，北京时间）、数据标签、底部 2~4 行关键数字汇总、最后一行脚注（口径边界/不可比说明）。

## 3. 发图前必做校验（省掉来回返工）

用 `vision_analyze` 传本地 PNG 绝对路径，问：中文是否方块 / 柱线是否清晰 / 图例是否遮挡数据 / 底部文字是否被裁切 / 可直接发店长吗。
有裁切或遮挡就改布局重跑，再校一次，然后才发群。
**顺手让 vision 复读一遍图内文案**（标题、副标题、脚注都算）：实测抓到过脚注语病（「弹性的为假设值」→ 应为「弹性 ε 为情景假设值」），图会直接发到群里，错字比排版问题更掉分；改动后重跑一次出图脚本再发。

## 4. 正文规矩

- 回复 = 短文字结论（≤3 条）+ `MEDIA:<绝对路径>`；不要在正文复述图中所有数字。
- 内容同时有逐行明细（14 天在手、10 个时段计划、8 个促销等）时：图给趋势、`send_operator_document` 给明细表，两者一起发，群里只留结论。
- 图上每个数字都必须能对上本轮 MCP 回包；口径与读取时间同时写进图内副标题和正文。
- 口径易混点要在图上和正文都点出来（实例）：金字塔未到投放时段的计划今日花费为 0，折线是**预设出价**不是已花钱；日历价（公开页）与 EBK 预埋价是两种口径，同一天可差 20~30 元，不能混用。

## 5. 实例（2026-10-13 三张图）

- 金字塔：柱=各时段今日花费、折线=点击出价（双轴），柱顶标「花费元/点击次」，暂停与待投放时段单独标注；配 `ad_pyramid` 全天总览文字块。
- 未来 14 天 vs 竞争圈：柱=在手间夜、双折线=本店/竞争圈出租率，顶部用色块标签标每日胜负（绿领先/灰持平/红输）。
- 去年同期按星期：左右双子图（出租率、过夜价），组内柱=今年 vs 去年，顶部贴间夜「今年/去年＝倍数」标注框，缺基线位置竖排「无基线」。

## 6. 实例（2026-10-14 价格影响测算图）

左右双子图，一次说清「历史规律 + 未来情景」：

- 左图：柱=各月日均预订订单（左轴）、折线=各月预订均价（右轴），柱内白字标出租率，副标题直接写结论「均价越低的月份，日均进单越多」——双轴图很适合表达「价-量」反向关系。
- 右图：折线=日销售额（左轴）、折线=日均订单（右轴），共享弹性 x 轴；`axvline` 在分水岭 ε=−1.0 处画绿色虚线并贴文字标注，`axhline` 画现状基准线并标数值；关键弹性点上用 `ax3.annotate` 标订单数标签。
- 图内脚注必须写「弹性 ε 为情景假设值，非本店实测」，与正文口径一致；这类测算图唯一的追责点就是没写这句。
