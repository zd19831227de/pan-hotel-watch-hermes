# 一群双店：群配置与路由场景

## 场景描述

同一个飞书群同时绑定两家酒店：
- **静里全套房酒店（云州澜江路望川路地铁站店）** — 关联 EBK 经营数据（`ctrip_ebooking_data_center`）
- **泉吉云州澜江路步行街高空江景酒店** — 关联竞品价格盯盘

## 路由规则

- "静里" → EBK 经营数据（出租率、ADR、间夜、订单、好评）
- "泉吉" → 竞品价格盯盘（最新价、趋势、变化提醒）
- 用户若只说「本群」不带店名 → 实际上一群双店，需列两家店请用户确认

## 竞品组注意事项（重要：两个独立竞品监控组）

**本群有两个独立的竞品监控组，各管各的，不是一组管两家店：**

| 监控组名 | 监控对象 | watch_group_key |
|---------|---------|----------------|
| 澜江路泉吉酒店 | 泉吉云州澜江路步行街高空江景酒店 + 2 家竞品 | `default_competitor_watch` |
| 静里全套房酒店（云州澜江路望川路地铁站店） | 静里 + 其竞品 | `watch_1782109266413` |

**关键约束：**
- **禁止**说「竞品组覆盖两家店」——这是错误说法。
- 暂停/恢复操作时，必须先确认用户指的是泉吉组还是静里组，然后在 `pause_watch` / `resume_watch` 的 `watch_group_key` 参数中传入正确的 key。
- 操作回复中必须明确说明操作的是哪个组，以及另一个组不受影响。
- EBK 监控组 `ctrip_ebooking_data_center` 绑定的是静里，与两个竞品组是两套独立系统。

## 常见对话模式

```
用户: "今天出租率多少"
→ 歧义（两家店都有出租率概念，但竞品盯盘不读出租率）
→ 正确：默认问 EBK，走 read_ebk_datasets(store_hint="静里")
→ 若用户说「泉吉今天出租率」，则同样走 EBK — 但注意此时是泉吉的 EBK，不是竞品数据
```

```
用户: "泉吉竞品最新价"
→ 清晰：竞品数据，走 get_competitor_latest_prices(store_hint="澜江路泉吉")
```

```
用户: "暂停静里的竞品酒店盯盘"
→ 正确做法：先 list_watch_groups 确认静里对应的竞品组 key（watch_1782109266413，不是 default_competitor_watch），然后 pause_watch(watch_kind='competitor', watch_group_key='watch_1782109266413')。
→ 回复时明确说「已暂停静里竞品组」「泉吉竞品组不受影响」
→ 错误做法：认为竞品组是共享的，说「该竞品组同时监控静里和泉吉，暂停会影响泉吉」
```

```
用户: "恢复这两家酒店的竞品盯盘轮询"
→ 注意：两家酒店各有一个竞品组，不能用一个操作恢复两个组。
→ 正确做法：先 list_watch_groups 确认哪个组当前是 paused，针对未启用或已暂停的组调用 resume_watch。如果两组都是 enabled=true，说明已在运行中，只需告知用户。
```
