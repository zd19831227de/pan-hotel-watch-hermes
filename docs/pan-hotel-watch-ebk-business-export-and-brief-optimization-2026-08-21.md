# EBK 经营数据简报与导出格式优化方向（对标携程「数据简报」）

> 创建日期：2026-08-21
> 性质：**开发方向设计文档，未修改任何代码与数据。**
> 对标基准：携程 EBK 官方「2026-08-20 数据简报」卡片字段（用户提供）。
> 上位约束：`AGENTS.md`「Real data first / 不发明经营数据」；本文档所有补字段
> 方向都基于「页面真实展示 → 解析 → 持久化」链路，不做模型推算编数。

---

## 一、现状：经营数据的三个出口

| 出口 | 位置 | 现状结构 |
|------|------|---------|
| ① 每日数据简报卡（Feishu） | `backend/app/domain/ctrip_ebooking_watch/service.py:166 run_daily_brief` → `messages.py:71 build_data_center_watch_push_card` | **只读 2 个数据集**（`DAILY_BRIEF_REQUIRED_DATASET_IDS = ("business_outline", "comment_monitor")`，repository.py:44）。固定三区：服务概览（PSI/点评分/5分钟回复率/收藏数）+ 点评跟进（昨日好评/差评）+ 点评概览 |
| ② 盯盘推送卡（Feishu） | 同 `messages.py`，手动/定时跑全量数据集 | 每数据集区块 + 通用指标罗列，**每集限 8 行**（`_generic_dataset_card_elements`），超出截断 |
| ③ 导出文件（CSV/XLSX） | `backend/app/api/v1/exports.py:221 /export/ebk-business-data` + `domain/exports/ebk_business_metrics.py` | XLSX 双 Sheet：「核心指标对比」（`CORE_HEADERS`：快照时间/平台/账号/销售额/订单量/间夜量/出租率/平均房价/转化率）+「经营明细」（`DETAIL_HEADERS`：快照时间/平台/账号/酒店/数据集/维度/指标/数值/数据口径/读取状态）；CSV 仅明细长表。**快照粒度**：每快照一行，无日聚合、无环比/同比、无趋势 |

解析层（`ctrip_ebooking_dataset_parsers.py`）已覆盖 9 个数据集 + 点评分析，指标
带统一结构（value/last_week_same_period/week_over_week/change/competitive_rank/
competition_average/section/display_value），这是简报卡和导出的共同上游。

## 二、对标字段逐项对比（官方简报 vs 本系统）

对标基准字段 → 解析层（能否读到）→ 每日简报卡（是否推送）→ 导出（是否含）：

|---------|--------|--------|------|------|

| APP访客数 | 有：`ctrip_app_visitors`（competition_profile） | 否 | 随明细 | A 类：数据在，卡片没纳入 |

| APP流量转化：详情页访客量 231 | 有：`app_detail_visitors` | 否 | 随明细 | A 类 |
| APP流量转化：订单页访客量 20 | 有：`order_page_visitors` | 否 | 随明细 | A 类 |
| APP流量转化：**订单提交人数 20** | **无**：全代码库无该指标 | — | — | **B 类缺口**：需核页面是否展示并新增解析 |
| 我的酒店 vs 竞争圈平均（曝光/下单/成交转化率） | 有：flow_data `exposure/booking/transaction_conversion_rate` + `competition_average` | 否 | 随明细（competition_average 未单独成列） | A 类 |

### 已发现的口径错位（真实 bug，建议 P0 修）

前端简报面板 `frontend/src/app/dataCenterBriefModel.ts:174`：UI 标签写
「较前一日」，实际取值是 `week_over_week ?? change`（**周环比**）。官方简报的
「较前一日」是自然日环比。修法二选一：
(a) 标签改「较上周同期」（与数据一致，纯前端文案）；
(b) 后端补 DOD 计算，标签保持（与 §四-2 聚合层一起做）。
在 DOD 能力就绪前，(a) 是诚实展示，优先做。

## 三、缺口分级

- **A 类（数据在解析层、卡片/导出未组织）**：离店三指标、预订订单数、APP访客、
  流量漏斗四项中的三项、竞争圈对比、排名表、competition_average 对比列。
  → 纯模板/导出编排工作，不新增读取。
- **B 类（解析层就缺，需扩读取或计算）**：城市排名 DOD、PSI DOD、订单提交人数、
  「本月」维度、全平台口径标注、同比、指标说明。
  → 需核页面真实展示（订单提交人数/本月区块/同比是否在页面上）→ 扩 parser；
  DOD 类靠后端相邻快照计算；同比若页面不展示则必须等满一年历史，**不得推算**。
- **C 类（口径错位）**：较前一日 vs 周环比（§二末）。前端文案先行修正。

## 四、优化方向（按实施顺序建议）

### 1. P0 口径错位修复（小改，先行）

- `dataCenterBriefModel.ts:174` 标签与取值对齐（TDD：前端测试断言标签文本）。
- 导出明细「数据口径」列（`_time_dimension_label`）已写时间档，但不含
  指标维度口径（离店/预订/实时、全平台/携程渠道）。方向：`_monitor_metric()`
  产出的 `section` 与指标口径说明统一落「数据口径」列。

### 2. P1 每日简报卡模板重构（对齐官方简报分区，不加读取成本）

把 `DAILY_BRIEF_REQUIRED_DATASET_IDS` 从 2 个扩到 5 个
（+ `beneficial_data` / `flow_data` / `competition_profile`），卡片重排为：

```
头部：日期 + 酒店名 + 城市排名（较前一日 ▲N，DOD 就绪前先只显示排名值）
本月经营概览：间夜量/平均卖价/销售额（同比列就绪前不显示百分比，不做推算）
昨日经营：离店销售额 / 离店间夜量 / 预订订单数 / APP访客 / APP转换率
点评分与点评：点评分 N · 昨日好评 x · 昨日差评 y（沿用现有三区合并）
PSI：N（较前一日 +Δ，DOD 就绪前只显示值）
APP流量转化漏斗：列表页曝光 → 详情页访客 → 订单页访客 → 订单提交人数
竞争圈对比：曝光/下单/成交转化率「我的酒店 vs 竞争圈平均」双列
尾注：指标说明（固定文案：城市排名/APP访客/点评分/PSI/APP流量转化为携程数据；
      间夜量/平均卖价/销售额为离店维度全平台数据；APP转化率=预订订单数/详情页访客量）
```

- 卡片构建仍集中在 `messages.py`，新增分区渲染函数 + 单测（fake payload 断言行）。
- 「订单提交人数」「本月区块」依赖 B 类补采，模板先留位、数据未就绪时整行隐藏
  （真实数据优先原则：宁缺勿造）。
- 指标说明尾注是**静态口径文案**，可直接从官方简报移植（它本身就是口径说明，
  不是经营数据）。

### 3. P2 日聚合层 + DOD 计算（B 类的核心基建）

现状：`ctrip_ebooking_watch_dataset_results` / `ebk_read_snapshots` 都是
「每次读取一行 JSON」，无按天聚合。方向：

- 新增轻量日聚合（每日简报成功读取后落一行「日指标表」，或导出时按天
  取每日最后一次成功读取做内存聚合，先做后者验证价值再落表）；
- DOD = 今日成功读取 vs 昨日同期简报读取的同指标 diff（城市排名、PSI 两个
  官方简报明确带「较前一日」的指标先行）；
- DOD 只在两天都读取成功时展示，否则省略（不推算、不填 0）。

### 4. P3 月度维度与同比（依赖核验，最重的一档）

- 先人工核验携程 EBK「经营概览」页是否本身展示「本月经营概览 / 本月全平台
  离店数据 / 较去年同期」区块（官方简报的该区大概率来自页面）；
- 若页面有：扩 `TIME_DIMENSION_SPECS` + `_extract_business_outline_dataset_metrics`
  提取本月区块与同比原文值（页面给多少展示多少，缺则隐藏）；
- 若页面没有：基于 P2 日聚合自算月累计，同比必须等满一年历史数据，
  **期间一律不显示同比**。

### 5. P4 导出格式与样式优化

现状问题：明细长表可用但偏「开发者视角」；核心宽表只有 6 指标、快照粒度、
多快照重复行；携程行「酒店」列为空（`_rows_for_snapshot` 的 base 只给
美团/飞猪填 `hotel_name`，携程侧 `酒店=""`）。方向：

1. **新增「日报」Sheet**（xlsx）：每平台每账号每日一行，列对齐官方简报分区
  （城市排名/排名DOD/离店三指标/预订订单/APP访客/转化率/PSI/PSI DOD/点评分/
  昨日好评差评/漏斗四项），数据来自 P2 聚合层；CSV 增加同构宽表端点或参数。
2. **「月度汇总」Sheet**：按月聚合（依赖 P3），含同比列（就绪前留空）。
3. **样式**（`xlsx_builder.py` 扩展）：表头加粗+冻结首行、数值列右对齐、
   日期列统一格式、负面变化（排名上升=数字减小）不染色规则先不做（避免误导），
   平台列用中文标签（已有 `PLATFORM_LABELS`）。
4. **口径完整化**：明细表「数据口径」列拼装 `时间档 + 指标维度（section）+
   渠道口径（全平台/携程渠道）`；核心表表头改双行或加「口径说明」Sheet
  （列名后缀 (离店/全平台) 等）。
5. **酒店列补全**：携程快照 payload 若无酒店名，从监控组配置
  （`CtripEbookingWatchGroup`）或账号别名回填，不再留空。
6. **指标说明 Sheet**：与卡片尾注同一份口径文案（单一出处，卡片/导出引用）。

### 6. P5 订单提交人数补采（B 类，需核页面）

官方简报「订单提交人数」大概率在流量数据页（flowdata）或竞争画像页展示。
方向：人工核验 → `_extract_flow_data_dataset_metrics` /
`_extract_competition_profile_dataset_metrics` 增加指标键
（如 `order_submitters`）→ 简报漏斗区与导出日报列同步接入。页面没有则不造。

## 五、三平台口径警示（导出与简报通用）

1. 「全平台离店数据」是 EBK 页面的**全渠道口径**（含直销/OTA 全部），与竞对监控
   的携程渠道价、与美团/飞猪快照的**平台自身口径**都不可直接比较。跨平台核心
   指标对比 Sheet 必须保留平台列 + 口径列，禁止隐式混排。
2. 美团/飞猪快照沿用各自页面指标名（`MEITUAN_DATASET_LABELS` /
   `FLIGGY_SECTION_LABELS`），「日报」Sheet 的跨平台列只在口径可对齐的指标上
   合并（沿用 `CORE_METRIC_CANDIDATES` 的候选键模式），对不齐的保持平台独立列。
3. 同比/环比一切数值必须来自页面原文或两个真实成功读取的差值；读取缺失时
   留空，不得线性插值或回填。
